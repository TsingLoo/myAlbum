# Immich AI configuration

Captured on 2026-07-25 for Immich `v3.0.3`.

## Models

The machine-learning container preloads the following CPU models. Their exact
environment variables are defined in `services/immich/docker-compose.yml`.

| Feature | Model |
|---|---|
| Smart Search (text and visual CLIP) | `ViT-B-32__openai` |
| Face Detection | `buffalo_l` |
| Facial Recognition | `buffalo_l` |
| OCR detection | `PP-OCRv5_mobile` |
| OCR recognition | `PP-OCRv5_mobile` |

Downloaded model files live in the Docker volume `immich_model-cache`. They are
a cache, not unique data, and will be downloaded again after a fresh deployment.

## Persistent state

Immich stores administrator settings, job state, face assignments, OCR output,
smart-search embeddings, albums, users, and asset metadata in PostgreSQL. They
are therefore preserved by the `database.sql.gz` generated by
`scripts/immich-cloud-backup.sh`.

The current explicitly stored server setting is:

```json
{
  "storageTemplate": {
    "enabled": true
  }
}
```

Other settings currently use Immich `v3.0.3` defaults. Pinning the Immich
release makes those defaults reproducible.

The `Active` and `Waiting` numbers on Administration > Jobs are live queue
counters, not configuration. Do not commit or restore those counters manually.

## Recovery

Restore the matching PostgreSQL dump to recover AI results and settings. Start
the machine-learning container afterward; it will reuse its model cache when
available or download the pinned models again. If generated thumbnails were not
backed up, run the corresponding missing-thumbnail and machine-learning jobs.
